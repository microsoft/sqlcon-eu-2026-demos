# Lessons

- An ODBC driver-name prefix is acceptable, but any other per-client connection-string translation invalidates this demo.
- Test connection-string values against each driver. ODBC 18.7.1.1 rejects `Encrypt=true` and `Authentication=ActiveDirectoryDefault`; Go rejects ODBC's `TrustServerCertificate=no` form.
- The same `Authentication` value can select different credential types per driver, so a passing connection does not prove the drivers did the same thing. Verified in source: SqlClient v7.1.0 `ActiveDirectoryIntegrated` calls MSAL `AcquireTokenByIntegratedWindowsAuth` (`ActiveDirectoryAuthenticationProvider.cs` line 348), while go-mssqldb v1.11.0 has no integrated branch and falls through to `NewDefaultAzureCredential` (`azuread/configuration.go` line 465, "Integrated just uses Default until azidentity adds Windows-specific authentication").
- `ActiveDirectoryDefault` is the one mode confirmed to resolve to the same credential type in both included drivers: `DefaultAzureCredential` in SqlClient and the same fall-through in Go.
- Route PyPI and NuGet through `packagefeedproxy.microsoft.io`; set `PIP_CONFIG_FILE` explicitly because Windows pip does not discover a repo-root config.
